## Cutover steps (Mac mini, ~10 min, gateway down ~1 min)
0. Coordinate: make sure no other Claude/Codex session is editing `~/.hermes/config.yaml` or
   restarting the gateway (one was active on 2026-09-09).
1. Snapshot state:
   ```bash
   hermes backup --quick --label pre-0.21.0
   ```
2. Fast-forward main (no history rewrite; branch is main + new commits):
   ```bash
   cd ~/repos/hermes-agent-dev && git status --short && git merge --ff-only merge/upstream-0.21.0
   ```
3. Sync Python deps into the live venv. Dry run (2026-09-09) showed the only change is
   firecrawl-anydoc 0.2.4 added and hermes-agent metadata 0.20.4 -> 0.21.0; every other package keeps
   its current version. Do NOT use `.[all]` / `.[messaging]` extras: they would downgrade numpy
   2.4.6 -> 2.4.3 and churn dev pins.
   ```bash
   cd ~/repos/hermes-agent-dev && ~/.hermes/bin/uv pip install -e . --python venv/bin/python
   ```
4. Rebuild the Node side (root workspace + dashboard bundle; dashboard runs `--skip-build` so
   `hermes_cli/web_dist` must be rebuilt by hand):
   ```bash
   cd ~/repos/hermes-agent-dev && npm ci --ignore-scripts --no-audit --no-fund && npm run build --workspace web
   ```
5. Config check (no migration will run: live config is v39 and 0.21.0's latest is also v39; the
   dry run showed an empty diff). `hermes doctor` is a pure check here:
   ```bash
   ~/repos/hermes-agent-dev/venv/bin/hermes doctor
   ```
   Expect: version files consistent (0.21.0), config v39 up to date. Known pre-existing noise if you
   run `migrate_config` by hand: 7 warnings about toolsets `a2a` and `no_mcp` (same on 0.20.4).
   `npm audit` will still report web/agent-browser advisories; build-time tooling only.
6. Restart services:
   ```bash
   launchctl kickstart -k gui/$(id -u)/ai.hermes.gateway && launchctl kickstart -k gui/$(id -u)/ai.hermes.dashboard
   ```
7. Verify:
   ```bash
   curl -s http://127.0.0.1:9119/api/status | python3 -c "import sys,json;d=json.load(sys.stdin);print(d['version'],d['gateway_state'],list(d['gateway_platforms']))"
   ```
   Expect `0.21.0 running ['ntfy','api_server','discord', ...]`; then send a message in #the-holler.
   Key on the `0.21.0` version string, not the commit line (`hermes --version` labels the pre-merge
   main tip as "upstream" via its stale-ref fallback).

### Live-gateway incident during the test run (2026-09-15)
Running `scripts/run_tests_parallel.py` over tests/gateway with a scratch `HERMES_HOME` still restarted
the live gateway at 11:02:39 CDT ("Stopping gateway for restart...", launchd relaunched it at 11:02:49,
all four platforms back) and at 11:06:58 a pytest subprocess running `tests/gateway/test_feishu.py`
overwrote `~/.hermes/gateway_state.json` (pid/argv of the test process, code_sha of the merge branch).
Cause: upstream tests rebuild `os.environ` with `clear=True`, which drops both `HERMES_HOME` and the
`HERMES_TEST_ISOLATION` marker, so the fork's env-only status guard (f4c86ae) was disarmed at the same
moment the home fell back to production. Fix on the branch (2aa573d1c9, c27b0a7856): status writes,
the control-socket client (pause-for-update drains and exits the gateway) and `start_gateway`
(`--replace` takeover) all refuse the passwd-derived production root while
`hermes_state_guard._in_test_context()` is true (env marker, backed by pytest process ancestry).
The stale `gateway_state.json` record is rewritten by the gateway on its next state transition (the
cutover restart does it); `hermes gateway status` keys on launchd and already reports correctly.
